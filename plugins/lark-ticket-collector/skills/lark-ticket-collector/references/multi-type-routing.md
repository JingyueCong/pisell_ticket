适用空间：`v2qint` / Pisell项目管理。在线核验日期：2026-09-28。本文件只记录已经完成真实创建与字段回读的三类高频工单；这属于创建级验证，不代表当前节点必填项已经全部审计。完整类型目录见 [Pisell 全类型路由](all-type-routing.md)，流程完整性见 [创建后的流程就绪检查](workflow-readiness.md)，结构化专项快照见 [work-item-routing.json](../../../workspace/configuration/work-item-routing.json)。快照仅用于定位和测试，提交前必须刷新 `project search`、`meta-types`、`meta-create-fields`、相关 `meta-fields` 与模板选项。

## 先分类，再读对应元数据

显式类型优先：用户说“客服工单”“需求池”“T-BUG”等时直接进入对应草稿。没有显式类型时：

- 已有功能出现错误、异常、状态不一致或无法使用 → 阻断性问题。
- 希望新增能力、改进交互或改变产品行为 → 需求池。
- 客户咨询、运营/售后跟进、商务或内容维护请求 → 客服工单。
- 同时符合两类或无法唯一判断时，只展示这三类让提交人选择；通常禁止一次消息自动创建多张跨类型工单。客服工单的“对应问题类型”已明确选择 T1/T2、T3 内容维护、T5 需求、客户刷卡机或风控处理时属于已授权例外，分别按 [客服工单与阻断性问题联动](customer-service-blocking-linkage.md) 或 [客服工单与业务工作项联动](customer-service-paired-workitem-linkage.md) 创建或复用配套项。

去重必须限定在目标类型内执行。标题相似只列候选，不自动合并；业务键精确命中仍按主技能的去重规则处理。

## 阻断性问题

继续使用 [Pisell 阻断性问题收单字段](pisell-intake-fields.md) 的完整规则。当前 type_key 为 `67df88cf656f61b9b41455d3`，唯一模板为默认流程 `2769525`。附件字段为“缺陷相关截图或视频” `field_7ea900`。

只有这一类型会在创建并回读后按生产 `handoff` 配置通知 Yoko CLI，请求进入根因拆解。其他两类不得套用 `task拆解指派`、T-BUG、Lv 等级或 Yoko 根因交接规则。

## 需求池

当前 type_key `67ee41797f03010701cea7c6`，接口必填只有名称与模板。员工输入至少应包含清晰的需求名称或需求描述；描述写入 `description`，客户/店铺能唯一解析时可写 `field_5cd576`，明确 P0/P1/P2 时写 `priority`，附件写 `field_62493b`。

模板路由：

- 普通功能建议或改进 → “常规评估规划流程类型” `2823040`。
- 明确付费开发、有偿开发或需要报价 → “付费开发评估流程类型” `3012664`。
- 明确综合设计或独立 UI/UX 设计任务 → “综合设计任务流程” `3310913`。

若正文只写“设计一下”但无法判断是产品需求还是独立设计任务，必须询问模板；不能凭关键词模糊命中。优先级和客户不是 API 创建必填，未提供时不编造。

2026-09-28 在线测试单 #7126715164 使用常规模板创建并回读成功，流程版本 25，当前节点“产品框架评估”。测试值不得作为业务默认值。

## 客服工单

当前 type_key `6886d47112cff2ae4ae279e3`，唯一模板“默认客服工单类型” `3399515`。创建前必须具备：

- 名称与描述 `description`。
- 问题来源 `field_20a3c6`：企业微信、WhatsApp、客服专用邮箱、飞书商家群、Zendesk、线下销售/运营转述反馈之一或多个。
- 对应问题类型 `field_5e764e`：T1核心阻断、T2非核心阻断、T3内容维护、T4商务、T5功能建议/需求、内部跟进、客户情绪/公关、客户刷卡机、风控处理、上门服务之一或多个。`上门服务` 已于 2026-10-06 在飞书项目在线字段中新增并保存；写入时仍须刷新在线 option_id，不硬编码快照值。
- 工单问题等级 `field_636ce3`：1 至 4 星。员工未明确给出时，按 2026-10-03 用户授权默认三星；员工明确给出合法星级时覆盖默认。写入前刷新在线选项并按“🌟🌟🌟”显示名称匹配 option_id，不能固定快照 ID。
- 客户管理 `field_5fe6c7`：按 CRM 唯一解析，禁止用店铺号代替工作项 ID。
- 商家问题提出人 `field_91fbb2`：保存真实姓名/联系方式或员工提供的可识别文本；不能用 CLI 登录人冒充商家提出人。
- 下次跟进时间 `field_234f83`：仅当“对应问题类型”包含“内部跟进处理”时显示并成为条件必填项。2026-09-28 的 `ErrFieldRequired` 来自该内部跟进分支，不能外推成所有客服工单的全局必填。命中该分支时不得默认“明天”，必须由提交人提供；其他类型不询问、不写入。

普通多选字段按 `[{"option_id":"..."}]` 的 JSON 字符串协议写入，客户关联写数字 ID 数组字符串。附件字段为 `field_f0d460`。不得把“飞书内部员工群”自动映射成“飞书商家群”；来源不明时询问。

当在线 `field_5e764e` 包含 T1 核心阻断或 T2 非核心阻断选项时，必须同时读取 [客服工单与阻断性问题联动](customer-service-blocking-linkage.md)。客服关联阻断字段当前定位为 `field_d1511f`，但写入前必须在线核对目标类型。联动规则负责两类独立查重、严格 bundle 门禁、自动字段映射、写入顺序、部分失败恢复和 Yoko 边界；两张草稿未就绪时不得创建客服工单。

当在线 `field_5e764e` 包含 T3 客户代运营请求-内容维护、T5 功能建议/改进类-需求、客户刷卡机或风控处理时，必须同时读取 [客服工单与业务工作项联动](customer-service-paired-workitem-linkage.md)。当前在线客服侧关联字段分别为内容维护 `field_e48264`、需求池 `field_e5e3aa`、客户刷卡机 `field_baa8cb`、风控处理 `field_87d289`；目标侧反向客服字段分别为 `field_7e7ab1`、`field_9fc721`、`field_928eb4`、`field_4bf86b`。这些只是定位快照，写入前必须重新核对类型和关联目标。客服及所有命中目标未全部就绪时不得进行任何外部创建。T4 商务、内部跟进和客户情绪/公关仍不自动跨类型创建。

## 回读与通知

三种类型都必须回读：ID、名称、类型、模板、`template_version`、当前节点及本次写入的关键字段，并用 `url decode` 验证详情链接。

- 阻断性问题：遵循生产 Yoko CLI 交接规则。
- 需求池：只返回工单链接和产品评估节点；没有单独配置时不 @ Yoko。
- 普通客服工单：只返回工单链接和客服跟进节点，不 @ Yoko。客服联动 bundle 同时返回客服与所有配套项链接和关联状态；只有其中新创建的阻断性问题按生产规则 @ Yoko，内容维护、需求池、客户刷卡机和风控处理不通知 Yoko。

专用测试群的临时 Echo mention 仅验证飞书通知机制，不改变上述生产路由。
